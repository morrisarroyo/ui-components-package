# UI Components Package

React UI components that developers use to build applications for the
healthcare setting: the screens of an Electronic Health Record (EHR) system,
such as a clinic's patient list and a patient's record. Product teams assemble
them into their own apps, so every screen looks and behaves the same and is
accessible by default.

You choose a variant, a size or a label; each component owns its appearance
and its states: hover, focus, error, loading and disabled.

| Component | Use it for |
| --- | --- |
| [Button](?path=/docs/components-button--docs) | Triggering an action. |
| [TextField](?path=/docs/components-textfield--docs) | Entering one line of text, with a label, a hint and an error. |
| [Card](?path=/docs/components-card--docs) | Grouping related content under an optional title. |
| [Table](?path=/docs/components-table--docs) | Showing many records as rows, optionally clickable. |
| [DescriptionList](?path=/docs/components-descriptionlist--docs) | Showing one record's details as label/value pairs. |

Every colour, spacing, radius and type value comes from the
[design tokens](?path=/docs/foundations-tokens--docs).

## Usage

Import the stylesheet once at your app's root, and the components from the
package entry point:

```tsx
import 'ui/styles.css';
import { Button, Card, TextField } from 'ui';
```

## Principles

- **A small, typed set of props.** You set a variant or a label; you never pass
  a colour or a pixel value.
- **States are the component's job.** Hover, focus, error, loading and
  disabled are built in.
- **Accessible by default.** Labels are attached to inputs, everything
  clickable works from the keyboard, and disabled things are actually
  disabled.
